# 3Danmu

**v1.0.2**

非官方视频客户端,运行在装有自制系统的任天堂 3DS 上。
名字取自「3D」+「弹幕」—— 3 当 E 用,3Danmu 里既有 3DS 的 3D,也有弹幕。

> **非官方项目,与哔哩哔哩无关,未获其授权或认可。仅供学习交流,严禁用于商业用途。**
> 本项目不分发任何视频内容,不绕过付费/会员/地区限制,不去广告,不提供批量下载。
> 使用非官方客户端可能导致账号受限,风险自负。
>
> **与任天堂(Nintendo)亦无任何关联。**「Nintendo 3DS」是任天堂的商标。
> 本项目是运行在自制系统上的第三方程序,不含任何任天堂的代码、密钥或资源。
>
> 许可见 [LICENSE](LICENSE) 与 [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md)。

在一台 2011 年的掌机上刷 B 站:个性化推荐流、搜索(自带拼音输入法)、
扫码登录、在线播放 360P/480P(New 3DS 走 MVD 硬件解码,满帧)、
滚动弹幕与**发弹幕**、CC 字幕、**裸眼 3D**、历史与收藏、观看进度同步账号。

```
┌─────────────────────────┐
│  上屏 400x240           │   视频画面 + 滚动弹幕
│  (列表页则显示视频列表) │
├─────────────────────────┤
│  下屏 320x240 触控      │   按钮式 GUI(播放控制 / 列表操作 / 设置)
└─────────────────────────┘
```

## 硬件与系统要求

**必需**

- 3DS / 2DS 系列主机,已安装自制系统(Luma3DS + Homebrew Launcher)
  - 破解教程:https://3ds.hacks.guide(有中文版)
- 可用的 Wi-Fi 网络

**强烈建议**

- **New 3DS / New 2DS**:才有 MVD 硬件解码器,能满帧播放 480P;
  老 3DS/2DS 只能软解 360P,帧率约 17-25fps,复杂画面会掉帧
- **DSP 固件**:Rosalina 菜单(**L + 下 + SELECT**)→ Miscellaneous options
  → Dump DSP firmware,看到 `successfully written` 即可,
  生成 `sdmc:/3ds/dspfirm.cdc`。**没有它完全没有声音**
  (画面一切正常,所以很容易被误当成 bug)

**机型默认设置**(可在设置页改)

| 机型 | 清晰度 | 解码 |
|---|---|---|
| New 3DS / New 2DS | 480P | MVD 硬解 |
| 老 3DS / 2DS | 360P | 软解 |

## 安装使用

1. 把 `3danmu.3dsx` 拷到 SD 卡的 **`/3ds/`** 目录(不是根目录);
   放子目录 `/3ds/3danmu/3danmu.3dsx` 也可以,HBL 同样能扫到。
   字体和拼音词库都打包在 .3dsx 内(romfs),不需要额外拷文件
2. **dump DSP 固件**:Rosalina 菜单(**L + 下 + SELECT**)→
   Miscellaneous options → Dump DSP firmware,看到 `successfully written`
   即生成 `sdmc:/3ds/dspfirm.cdc` —— **没有它完全没有声音**
3. SD 卡插回主机,连好 Wi-Fi
4. 打开 Homebrew Launcher,选择 3Danmu 启动
   (想要免开 HBL、直接出现在主菜单,见 [DEVELOPING.md 的「打包成独立应用」](DEVELOPING.md#从源码编译),打好的 cia 用 FBI 安装)

**开发调试强烈建议用 `3dslink` 无线推送**(免插拔 SD 卡):
主机 HBL 里按 Y 进 netloader,电脑上 `3dslink 3danmu.3dsx`,
程序经 Wi-Fi 推过去立即运行。自动发现失灵时用 netloader 界面显示的 IP:
`3dslink -a 192.168.x.x 3danmu.3dsx`。注意推送运行的是内存副本,SD 卡上的旧文件
不会被更新,调稳定后记得拷一次卡。传其他文件(cia、字体)可以在 3DS 上
装个 ftpd,电脑用任意 FTP 客户端连,同样免插卡。

登录信息存在 `sdmc:/3ds/3danmu/cookies.txt`,下次启动自动恢复。

> ⚠️ `cookies.txt` 里是**有效的账号凭证**。发日志、发截图、把 SD 卡借给别人
> 之前记得处理掉,和密码同等对待。

### 万一登录后发不了弹幕

正常情况下扫码登录就够了,全部功能可用。但如果发弹幕时提示缺 `bili_jct`,
说明登录走的是**降级路径**(原因见
[DEVELOPING.md 的「为什么有个 tls.c」](DEVELOPING.md#为什么有个-tlsc))。
手动补一次即可,**做一次就长期有效**:

1. 电脑浏览器登录 bilibili.com
2. F12 → Application(应用) → Cookies → `https://www.bilibili.com`
3. 找到 `bili_jct`,复制它的值(32 位十六进制)
4. 编辑 SD 卡上的 `sdmc:/3ds/3danmu/cookies.txt`,加一行 `bili_jct=你复制的那32位`
5. 重启 3Danmu

同一个位置的 `SESSDATA` 也能这样导入,两个都填就等于登录,连扫码都省了。

### 下屏触控 GUI(主要交互方式)

**列表页**

```
┌──────────────────────────────────┐
│ 已登录 / 未登录                  │
│  ┌──────────┐  ┌──────────────┐  │
│  │   推荐   │  │    热门      │  │
│  └──────────┘  └──────────────┘  │
│  ┌──────────┐  ┌──────────────┐  │
│  │   历史   │  │    收藏      │  │
│  └──────────┘  └──────────────┘  │
│  ┌──────────┐  ┌──────────────┐  │
│  │   设置   │  │ 扫码登录/注销│  │
│  └──────────┘  └──────────────┘  │
│  [状态条:进度 / 按键提示]       │
└──────────────────────────────────┘
(搜索 = Y 键,翻页 = L/R,当前页面按钮高亮)
```

**播放页**:标题、播放时间 / 总时长、当前解码方式,
返回 / 暂停·播放 / **设置** / 弹幕开关 / **发弹幕** 按钮
(**播放设置子页**收纳:3D 开关、CC 字幕开关、弹幕字号、字幕字号(均小/中/大)、
调试台入口,右下角软解时是同步·流畅模式、硬解时是返回键(该模式对硬解无意义),
并实时显示字幕加载状态。B 键随时退出设置),
以及底部的**可拖动进度条**。

进度条用法:按住把手左右拖动,拖动时上方气泡显示目标时间;
**松手才真正跳转**,跳转后会短暂显示"缓冲中"。
(上屏原有一条细进度条,后已去掉——下屏控制条足够,画面留给视频和弹幕。)
命中区上下各放宽了 14 像素,手指也能操作。

**设置页**:

- **弹幕:开/关** — 是否加载并显示弹幕
- **清晰度:360P/480P** — 480P 需登录,取流失败自动回落
- **解码:自动/软解** — 自动 = New 3DS 优先硬解;软解 = 强制 ffmpeg 软解
- **调试台** — 切到全屏日志控制台(点触摸屏返回)
- **返回**

### 调试台

任意「设置」页 → 点「调试台」→ 手指**拖动滚动**、**双击**退出。
上下键也能滚。

它记录最近 400 行:网络请求、解码器状态、MVD 返回码等等。
**打开之前发生的事也都还在**,所以出问题之后再打开来得及 ——
排障最需要的往往正是那段历史。

出问题时把这一页拍下来,比任何文字描述都有用。

> 调试台输出**全是英文/ASCII**。动态内容(视频标题、接口返回的中文
> 错误信息)会被过滤成 `?`,所以看到 `>> ??????` 是正常的,那是中文标题。
> 上屏会显示完整中文。

日志页是 citro2d 自绘的,支持中文界面、触摸拖动、滚动条。
为什么不用 3DS 自带 console、以及这套日志踩过哪些坑,见
[DEVELOPING.md 的「调试方法」](DEVELOPING.md#调试方法)。

### 同步优先 vs 流畅优先(仅软解有意义)

软解速度不足时,播放器要在"音画同步"和"帧率"之间取舍:

- **流畅优先**(默认):落后音频 >400ms 才跳帧,画面延迟约 0.2-0.4 秒但更流畅
- **同步优先**:落后 >150ms 就跳帧,嘴型对得更准但跳帧更频繁

硬解速度远超需求,两种模式无差别。

## 已知问题与 TODO

### 已知问题

- **搜索结果结构会变**。服务端返回的结构随版本变化,代码里按几种已知形状
  依次尝试;若某天全部落空,调试台会打印响应头部便于定位新结构。
  这类适配随时可能失效,属于第三方客户端的常态
- ~~退出播放时可能有短暂延迟~~ **v1.0.0 已修**:退出/关闭时主动
  `httpcCancelConnection` 掐掉在途请求,各线程 join 压到 0.5 秒,
  实测全链路 190ms(修复过程见「3DS 开发踩坑记录」的 Closing software 条)
- **CDN 链接有时效**。断网超过一两小时后,即使重连也拉不到数据,
  退出重进即可
- **首次加载封面慢(约十几秒/页)**。3DS 网络栈单次往返就要几百毫秒,
  而每页 20 张图;实测总字节数才 46KB,即纯延迟受限。
  已确认**加线程、加并发、调优先级全部无效**(httpc 服务内部本就串行),
  唯一有效的是 SD 卡缓存 —— 所以"再看一次"是秒出的,"第一次"没救
- **字幕的首选取数路径长期不可用**,已自动降级到备用路径,
  **字幕功能不受影响**;首选路径哪天恢复会自动切回去
